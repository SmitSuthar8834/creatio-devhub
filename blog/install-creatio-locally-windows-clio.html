How to install Creatio locally on Windows with clio

By Smit Suthar · October 24, 2026 · 3 min read
Short answer

Prepare IIS (clio check-windows-features), a PostgreSQL or MS SQL server that clio knows about, and Redis. Then run clio deploy-creatio --zip-file C:\Builds\creatio.zip --site-name creatio-dev --db pg --db-server-name my-pg from an administrator prompt. clio extracts the build, restores the database, creates the IIS site and picks a free port. clio uninstall-creatio -e creatio-dev removes it again.

A local Creatio instance is the fastest place to develop: no shared environment to break, no waiting for someone else's restart, and file system mode for your IDE. Setting one up by hand means IIS, a database restore, connection strings and Redis. clio's deploy-creatio command does most of that in one step.

What you need

  • A Creatio distribution zip for the product and database type you want, from your Creatio account or partner channel.
  • Windows with IIS. Check the required features with clio check-windows-features, and install missing ones with clio manage-windows-features.
  • A database server: PostgreSQL or MS SQL, registered in clio's settings (open them with clio open-settings). For PostgreSQL, pg_restore must be available on the machine running clio. clio can also restore into a Kubernetes setup such as Rancher Desktop.
  • Redis, running locally.
  • An administrator prompt, because clio creates IIS sites.

Install

clio deploy-creatio --zip-file C:\Builds\creatio.zip --site-name creatio-dev --db pg --db-server-name my-pg

What the options do:

  • --zip-file: the distribution zip, or an already-extracted folder to skip unzipping.
  • --site-name: the IIS site name.
  • --db: pg for PostgreSQL (the default) or mssql.
  • --db-server-name: the database server configured in clio's settings. Without it, clio uses its Kubernetes restore flow.
  • --site-port: optional. Otherwise clio takes the first free port in its range, 40100 to 40199 by default.
  • --use-https: optional, if a matching local certificate is installed.

clio also finds an empty Redis database by itself unless you pass --redis-db. When it finishes, open the site; the first sign-in to a fresh instance can take a few minutes while Creatio starts.

Remove it cleanly

clio uninstall-creatio -e creatio-dev

Use the name the environment is registered under in clio. This removes the IIS site or application, the database and the application files. There is no undo, so double-check the name. You can point it at the installation folder instead, with -d C:\inetpub\wwwroot\creatio-dev.

When it fails

  • Port in use: an explicit --site-port that is taken fails; leave it out to let clio pick a free one.
  • pg_restore not found: install the PostgreSQL client tools and make sure they are on PATH.
  • Redis not running: start it before deploying; Creatio will not start without it.
  • Access denied: run the prompt as administrator.
  • Database already exists: pick a different site name rather than overwriting a database you may still need.

Next steps

Register the new environment if it isn't already (clio reg-web-app), install cliogate with clio install-gate -e creatio-dev, and turn on file system mode with clio turn-fsm -e creatio-dev on if you want to edit packages from your IDE. Then put your packages in Git: here is how.

The one-window way

On Windows, Companion for Creatio has Install Creatio on its Environments screen. Pick the zip (the database type and runtime are read from its name when it says), a site name, an optional port and a database server set up in clio, or Rancher / Kubernetes. Before anything is created it checks administrator rights, the build, that the site name and port are free, the database server including pg_restore, and Redis, and it never overwrites an existing database. Uninstall Creatio asks you to type the name first, and Import from IIS registers Creatio sites already on your machine.
